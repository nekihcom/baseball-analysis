# 草野球データ収集ツール 要件定義書

| 項目 | 内容 |
| --- | --- |
| 版数 | 0.4 |
| 作成日 | 2026-10-26 |
| ステータス | 承認済（2026-10-26） |

## 1. 目的

草野球チーム管理サービス「teams」（https://teams.one/teams/ ）で公開されているチームのデータを定期的に収集し、Google スプレッドシートに蓄積する。蓄積したデータは将来の分析に用いる。

## 2. スコープ

### 2.1 対象

- teams 上で公開されているチームページからのデータ収集
- 収集データの CSV 化
- Google スプレッドシートへの保存とバックアップ
- GitHub Actions による週次自動実行

### 2.2 対象外

- データ分析機能（分析方式は未定のため、本書の対象外とする）
- ログインが必要なページからの収集
- 選手個人ページ（選手名鑑）からの収集

## 3. 用語

| 用語 | 定義 |
| --- | --- |
| チームID | teams の URL 中でチームを一意に識別する文字列。`https://teams.one/teams/{チームID}/` の形式で現れる（例：`orcas`） |
| 収集データ | 収集処理で作成する最新データ |
| バックアップ | 収集処理の直前に存在した収集データの写し |
| 対象年度 | 打者・投手の年度別成績を取得する年度 |

## 4. システム構成

| 項目 | 内容 |
| --- | --- |
| 実装言語 | Python |
| 実行環境 | GitHub Actions（スケジュール実行および手動実行） |
| 収集元 | https://teams.one/teams/ |
| 保存先 | Google スプレッドシート（1 ブック。データごとに 1 シートとし、全チーム分を同じシートに格納する） |
| CSV の保管 | 実行環境上の `repo/data/` に作成し、GitHub Actions の Artifacts として保存する |
| 認証 | Google サービスアカウント。認証情報は GitHub Secrets で管理する |

処理の流れは以下のとおり。

```
GitHub Actions（週次 / 手動）
  └─ 収集プログラム（チームIDを引数で受け取る）
       ├─ 1. スプレッドシートの現行シートを読み込み、data/bks/*.bk.csv を作成
       ├─ 2. バックアップCSVの内容をバックアップシート（*.bk）へ書き込み
       ├─ 3. teams から HTML を取得・解析
       ├─ 4. 現行シートの内容に対象チームの収集結果をマージし、data/*.csv を作成
       ├─ 5. 収集データCSVの内容をスプレッドシートの各シートへ書き込み
       └─ 6. data/ 配下を Artifacts としてアップロード
```

前回実行の CSV は実行環境に残らない。このため、前回のデータの取得元にはスプレッドシートの現行シートを使う。

## 5. 機能要件

### 5.1 実行方法

| ID | 要件 |
| --- | --- |
| FR-01 | 収集対象のチームIDを実行時引数で指定できること |
| FR-02 | 1 回の実行で複数のチームIDを指定できること |
| FR-03 | GitHub Actions のスケジュール実行で毎週金曜日 23:59（JST）に自動実行されること（cron は UTC 指定のため `59 14 * * 5` とする）。スケジュール実行時のチームIDはワークフロー定義または Actions の変数で与える |
| FR-04 | GitHub Actions の手動実行（workflow_dispatch）でチームIDを入力して実行できること |
| FR-05 | ローカル環境でもコマンドラインから同じ処理を実行できること |

### 5.2 収集対象データ

`{team}` はチームID、`{year}` は 4 桁の年度を表す。

| ID | データ | 取得元 URL | 備考 |
| --- | --- | --- | --- |
| FR-10 | スケジュール | `https://teams.one/teams/{team}/plan` | 「予定」のみ取得する。「過去」（`/plan/past_index`）は取得しない |
| FR-11 | 試合結果 | `https://teams.one/teams/{team}/game` | 1 ページ 20 件のページ送り（`?page=n`）があるため、全ページを取得する。試合属性・大会名などの絞り込みは行わず、全試合を取得する |
| FR-12 | チーム成績 | `https://teams.one/teams/{team}/stats` | 年度別行と通算行を取得する |
| FR-13 | 打者年度別成績 | `https://teams.one/teams/{team}/stats/batters_table?search_result%5Bgame_date%5D={year}&...&search_result%5Bunreached%5D=true` | 規定未到達者を含める。クエリの全体は CLAUDE.md の定義に従う |
| FR-14 | 投手年度別成績 | `https://teams.one/teams/{team}/stats/pitchers_table?search_result%5Bgame_date%5D={year}&...&search_result%5Bunreached%5D=true` | 同上 |

### 5.3 取得項目

各ページの表に表示されている全項目を取得する。加えて、全データに以下の項目を付与する。

| 項目 | 内容 |
| --- | --- |
| チーム（`team`） | チームID。全データの先頭列とする |
| 収集日時（`collected_at`） | 収集日時（JST、ISO 8601 形式） |

2026-10-26 時点で確認したデータ別の項目は以下のとおり。サイト側の変更で項目が増減する可能性がある（NFR-12 参照）。

| データ | 取得項目 |
| --- | --- |
| スケジュール | チーム、日時、種別（練習試合など）、タイトル（活動日など）、予定詳細ID（`/plan/{id}` の id） |
| 試合結果 | チーム、日時、試合属性（公式戦／練習試合／その他）、対戦チーム、スコア、サヨナラ有無（スコア末尾の `x`）、勝敗 |
| チーム成績 | チーム、年、試合、勝ち、負け、引分、勝率、得点、失点、打率、本塁打、盗塁、防御率 |
| 打者年度別成績 | チーム、年度、背番号、選手名、試合数、打率、打席、打数、安打、本塁打、打点、得点、盗塁、出塁率、長打率、得点圏打率、OPS、二塁打、三塁打、塁打数、三振、四球、死球、犠打、犠飛、併殺打、敵失、失策、盗塁死、盗塁阻止 |
| 投手年度別成績 | チーム、年度、背番号、選手名、試合数、勝、ホールド、セーブ、敗、勝率、防御率、投球回、投球数、失点、自責点、完投、完封、被安打、被本塁打、奪三振、与四球、与死球、ボーク、暴投 |

スケジュールと試合結果の「日時」は、ページ上の年・月・日・曜日をまとめた 1 項目とし、`YYYY-MM-DD` 形式で保存する。2026-10-26 時点で両ページの一覧には時刻が表示されないため、時刻は含めない。曜日は日付から導出できるため保存しない。

### 5.4 対象年度

| ID | 要件 |
| --- | --- |
| FR-20 | 対象年度は、成績ページの年度選択肢に表示される年度から決定する |
| FR-21 | 初回実行（対象シートに当該チームの行が存在しない場合）は、全年度を取得する |
| FR-22 | 2 回目以降の実行は当年度のみ取得し、既存データのうち当該チーム・当年度の行を置き換える。他チームの行と前年度以前の行は保持する |
| FR-23 | 全年度の再取得を引数で強制できること |

当年度は実行日（JST）の暦年とする。

### 5.5 CSV 作成

| ID | 要件 |
| --- | --- |
| FR-30 | データごとに 1 ファイルとし、以下のファイル名で `repo/data/` に作成すること。複数チームの行を同じファイルに格納する |
| FR-31 | 文字コードは UTF-8、1 行目をヘッダ行とすること |
| FR-32 | CSV の内容は、現行シートの内容に今回の収集結果をマージしたものとすること。マージでは、今回収集したチームの行（年度別成績は当該チーム・取得年度の行）を置き換え、それ以外の行は保持する |
| FR-33 | 実行終了時に `repo/data/` 配下（バックアップを含む）を GitHub Actions の Artifacts としてアップロードすること |

| データ | ファイル名 |
| --- | --- |
| スケジュール | `schedule.csv` |
| 試合結果 | `game_results.csv` |
| チーム成績 | `team_stats.csv` |
| 打者年度別成績 | `batter_year_stats.csv` |
| 投手年度別成績 | `pitcher_year_stats.csv` |

### 5.7 バックアップ

| ID | 要件 |
| --- | --- |
| FR-50 | 収集処理の前に、現行シートの全件（全チーム分）をバックアップ CSV として `repo/data/bks/` に作成すること |
| FR-51 | バックアップ CSV の内容を、データごとのバックアップシートへ全件置き換えで書き込むこと |
| FR-52 | バックアップは 1 世代のみ保持し、実行のたびに上書きすること。過去の世代は Artifacts の保持期間内に限り参照できる |
| FR-53 | 現行シートが存在しない場合（初回実行）はバックアップを作成しないこと |

### 5.8 エラー処理

| ID | 要件 |
| --- | --- |
| FR-60 | あるチームのあるデータの取得・解析に失敗した場合、そのチームの当該データは既存の行を維持すること |
| FR-61 | 複数チームを指定した場合、1 チームの失敗で他チームの処理を中断しないこと |
| FR-62 | 失敗が 1 件でもあれば、ワークフローを失敗ステータスで終了すること。失敗の通知は GitHub 標準の通知（ワークフロー失敗時のメール等）のみとし、独自の通知機能は設けない |
| FR-63 | 処理開始・終了、取得 URL、件数、エラー内容をログに出力すること |

## 6. 非機能要件

### 6.1 サイトへの配慮

| ID | 要件 |
| --- | --- |
| NFR-01 | リクエスト間隔を 1 秒以上空けること |
| NFR-02 | robots.txt を遵守すること（2026-10-26 時点で一般クローラーに対する対象パスの禁止はない） |
| NFR-03 | User-Agent に本ツールを識別できる文字列を設定すること |
| NFR-04 | 一時的なエラー（タイムアウト、HTTP 5xx）は間隔を空けて最大 3 回再試行すること |

### 6.2 保守性

| ID | 要件 |
| --- | --- |
| NFR-10 | 収集・解析・保存の処理を分離し、ページ構造の変更時に解析処理のみの修正で済むようにすること |
| NFR-11 | 解析処理は保存済み HTML を入力とする単体テストを備えること |
| NFR-12 | 表のヘッダ行から列を決定し、想定外の列の増減を検知した場合は警告をログに出力すること |

### 6.3 セキュリティ

| ID | 要件 |
| --- | --- |
| NFR-20 | Google サービスアカウントの認証情報はリポジトリに含めず、GitHub Secrets で管理すること |
| NFR-21 | スプレッドシートの共有範囲はサービスアカウントと利用者に限定すること |

### 6.4 性能

| ID | 要件 |
| --- | --- |
| NFR-30 | 1 チームあたりの処理が GitHub Actions のジョブ実行時間内（目安 10 分以内）に完了すること |

## 7. 制約事項

- 成績表の選手名はサイト側で省略表示（例：`いわた(…`）されており、HTML 上も省略後の文字列しか含まれない。選手の一意な識別は背番号と省略後の選手名の組で行う
- 本ツールはサイトの HTML 構造に依存する。サイト側の改修により収集できなくなる可能性がある
- GitHub Actions のスケジュール実行は指定時刻から遅延する場合がある。金曜日 23:59 の実行が日付をまたぐと、実行日が土曜日になる。12 月 31 日が金曜日の場合は当年度（FR-22）が翌年に変わり、前年分の最終更新が漏れる。この場合は FR-23 の全年度再取得で補う
